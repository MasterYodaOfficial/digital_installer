# Правила доработки

Перед изменением прочитайте README, TODO и описание затрагиваемой функции. Список планов не является доказательством реализации.

## Код и проверки

- Документацию и поясняющие комментарии пишите по-русски. Технические идентификаторы сохраняйте в принятом стиле проекта.
- Права проверяйте на сервере. Не доверяйте присланным клиентом ролям, идентификаторам и суммам.
- Изменения схемы сопровождайте миграциями. Не изменяйте уже применённые миграции без плана перехода.
- Для прав, состояний и расчётов нужны тесты успешных и запрещённых действий на изолированных данных.
- Перед коммитом выполните подходящие тесты и `git diff --check`. Для интерфейса проверьте сборку и затронутые сценарии.

## Документация каждой доработки

1. Обновите `CHANGELOG.md`: что изменилось и существенные ограничения.
2. Обновите `TODO.md`. Не отмечайте всю функцию готовой, если реализован только API или интерфейс.
3. Новую функцию или изменение контракта опишите в `docs/`: назначение, роли, точки входа, поведение, ошибки, файлы и проверка.
4. При изменении запуска обновите README. Различайте состояние исходников и действующего сервера.

## Публикация

Добавляйте только проверенные файлы. Не публикуйте секреты, дампы, рабочие фотографии, персональные данные, исходные таблицы, настройки помощников, переписку и коммерческие материалы. `documentation/` содержит локальные материалы и исключена из Git.

Сохраняйте историю проекта и локальные исправления на сервере. Git не заменяет резервирование, сборку и проверку работоспособности.
